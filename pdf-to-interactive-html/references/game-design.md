# Evidence-based game design

Use this reference when the requested HTML should be a quiz, quest, simulation, or educational game.

## Minimum complete loop

- A short premise and explicit goal.
- Multiple levels or rounds with visible progress.
- Player choices based on source evidence.
- Immediate feedback explaining why an answer is right or wrong.
- A score, collection, achievement, or other legible reward.
- A completion state and replay path.
- An evidence/source view outside the game loop.

Mechanics should reinforce the learning objective. Do not add points, timers, lives, or chance merely as decoration. A “life” should represent an attempt, not imply that an ambiguous inference is objectively wrong.

## Question construction

- Base each correct answer on the evidence ledger.
- Use distractors that expose a useful misconception, such as confusing aggregate growth with individual behaviour.
- Avoid trick wording and questions that require knowledge absent from the PDF.
- When the learning target is uncertainty, make “the report does not disclose this” a valid answer.
- Explain the source distinction after every response.

## Child-friendly adaptations

Use short sentences, concrete metaphors, supportive feedback, and an original guide character. Retain exact figures in a clearly labelled fact ribbon or evidence panel. Avoid manipulative urgency, commercial calls to action, external tracking, and collection of children’s personal information.

## Validation checklist

- Every correct answer agrees with the evidence ledger.
- Every cited page uses the document’s printed page number.
- Wrong answers cannot also be reasonably correct.
- The game can be completed with touch, mouse, and keyboard.
- Restart resets every score and progress variable.
- The final state reports achievement without overstating factual certainty.
